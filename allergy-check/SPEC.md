# 알레르기 체크 웹앱 — Claude Code 작업 명세서

> 이 파일을 프로젝트 루트에 `SPEC.md`로 두고 Claude Code에 "SPEC.md 읽고 MVP부터 만들어줘"라고 요청하세요.

---

## 1. 한 줄 요약

가족이 **식품 성분표 사진을 찍으면**, 아이의 알레르기 검사(MAST) 결과와 대조해서 **"먹어도 되나?"를 색깔·아이콘으로 바로** 알려주는 모바일 웹앱(PWA).

## 2. 사용자

- **주 사용자:** 중학생 본인. 편의점이나 학교 매점에서 혼자 확인함. 긴 글을 읽지 않음.
- **보조 사용자:** 부모와 가족. 장보기·외식 때 확인하고, 알레르기 정보를 설정·관리함.
- **원칙:** 3초 안에 결론. 터치 2번 안에 촬영. 글보다 색과 아이콘.

## 3. 핵심 기능 (MVP)

### 3-1. 📷 성분표 촬영 → 결과
1. 홈 화면에 **화면 절반 크기의 "📷 성분표 찍기" 버튼** 하나.
   - `<input type="file" accept="image/*" capture="environment">` 사용(앱 설치 없이 카메라 실행)
   - 갤러리 사진 업로드도 가능
2. 촬영한 이미지를 서버 API로 보내 **Claude API(비전)**로 성분 추출
   - 원재료명 목록과 알레르기 유발물질 표시란("○○ 함유"), "같은 제조시설에서 ○○ 제품 생산" 문구까지 구분해서 JSON으로 받기
   - 추출 결과와 사진 품질 신뢰도(high/medium/low)도 함께 받기
3. **매칭은 코드로(결정적으로)** 처리. LLM이 위험 여부를 판단하지 않게 함.
   - 추출된 성분 → 동의어 사전(아래 5번) → 알레르기 프로필 대조
4. 결과 화면 맨 위에 **큰 신호등 카드** 하나 + 아래에 걸린 성분 목록

### 3-2. 결과 화면 등급 (가장 높은 등급 하나를 맨 위에 표시)

| 등급 | 색 | 아이콘 | 문구 (중학생 눈높이) |
|---|---|---|---|
| 위험 | 빨강 | ⛔ | **먹지 마세요** — ○○이(가) 들어 있어요 |
| 주의 | 주황 | ⚠️ | **조심하세요** — 부모님께 물어보세요 |
| 참고 | 노랑 | 💡 | 약한 반응 성분이 있어요 |
| 해당 없음 | 초록 | ✅ | 내 알레르기 성분은 **못 찾았어요** |
| 확인 불가 | 회색 | ❓ | 글씨가 잘 안 보여요. 다시 찍어주세요 |

- 초록 문구는 절대 "안전해요"라고 쓰지 않음. "**못 찾았어요**"로 표현하고, 작은 글씨로 "성분표가 틀리거나 빠졌을 수 있어요"를 덧붙임.
- "같은 제조시설" 문구에 걸리면 한 단계 낮춰서 표시(위험 → 주의). 문구는 "공장에서 섞였을 수 있어요".
- 사진 인식 신뢰도가 low면 무조건 **회색**. 추측으로 초록을 띄우지 않음.
- 걸린 성분은 성분표 원문에서 **어떤 단어가 걸렸는지** 하이라이트(예: "유청분말 → 우유" / "새우추출물 → 새우").

### 3-3. 👤 내 알레르기 프로필
- 검사 결과를 항목별로 등록(아래 6번 초기 데이터 사용)
- **가족이 항목마다 실제 상태를 지정**할 수 있게 함. 등급보다 이 설정이 우선함.
  - 🔴 "먹으면 증상 있음" → 항상 **위험**
  - 🔴 "의사가 피하라고 함" → 항상 **위험**
  - ⚪ "아직 모름" (기본값) → 검사 Class 기준 등급
  - 🟢 "먹어도 괜찮음" → **참고**로만 표시
- 이유: 검사 양성(감작)이 곧 알레르기는 아님. 쌀처럼 Class 3이어도 매일 먹는 음식이 있으므로, 가족 설정이 없으면 경고가 너무 많아져서 아무도 안 쓰게 됨.
- 설정 화면은 **부모 PIN(4자리)**으로 잠금. 아이가 실수로 바꾸지 않게.

### 3-4. 기본 등급 규칙 (가족 설정이 "아직 모름"일 때)

| 검사 Class | 앱 등급 |
|---|---|
| 4~6 | 위험 |
| 3 | 주의 |
| 2 | 참고 |
| 0~1 | 표시 안 함 |

- 같은 음식에 성분 검사(component)가 있으면 둘 다 보여주고 높은 쪽을 따름.

### 3-5. 🕘 최근 검사 기록
- 찍은 제품 썸네일, 날짜, 결과 색을 목록으로 표시. 자주 먹는 제품을 다시 찍지 않아도 되게.
- 제품에 별명 붙이기(예: "매점 소시지빵").

### 3-6. 🆘 응급 버튼 (모든 화면 우측 하단 고정)
- 누르면 **119 바로 걸기** 버튼과 "숨쉬기 힘듦, 입술·혀 부음, 온몸 두드러기, 어지러움 → 바로 119" 안내만 표시.
- 약 이름이나 용량 같은 의료 지시는 앱에 넣지 않음. 의사가 처방한 응급약이 있다면 가족이 직접 메모로 입력하는 칸만 제공.

## 4. 화면 구성

```
[홈]
 ┌───────────────────────┐
 │  안녕! 오늘 뭐 먹어?   │
 │ ┌───────────────────┐ │
 │ │   📷 성분표 찍기    │ │  ← 화면 절반
 │ └───────────────────┘ │
 │  🖼 사진 불러오기       │
 │  🕘 최근 기록          │
 │                  [🆘] │
 └───────────────────────┘
 하단 탭: 홈 | 내 알레르기 | 기록 | 설정(🔒)

[결과]
 ┌───────────────────────┐
 │ ⛔ 먹지 마세요          │  ← 빨강 전체 배경
 │ 새우가 들어 있어요      │
 ├───────────────────────┤
 │ ⛔ 새우추출물 → 새우    │
 │ ⚠️ 효모추출물 → 효모    │
 │ 💡 대두 → 콩           │
 ├───────────────────────┤
 │ [원본 사진 보기] [다시 찍기] │
 └───────────────────────┘
```

**디자인 원칙**
- 최소 글자 크기 18px, 결과 제목은 32px 이상
- 버튼 높이 56px 이상
- 색만으로 구분하지 않음. 반드시 아이콘과 글자를 함께 표시(색각이상 대응)
- 다크모드 지원
- 전문용어 금지: "IgE", "Class", "감작"은 설정 화면에만. 아이 화면에는 "강한 반응 / 약한 반응"으로 표현

## 7. 기술 스택 (권장)

- **Next.js (App Router) + TypeScript + Tailwind CSS**
- **PWA**: 홈 화면에 추가 가능, 오프라인일 때 기록 조회 가능
- **이미지 분석**: 서버 API 라우트에서 Anthropic API 호출(비전 모델). API 키는 서버 환경변수에만 두고 클라이언트에 노출 금지
- **업로드 전 이미지 축소**: 긴 변 1600px, JPEG 품질 0.8
- **저장소**: 프로필과 기록은 **기기 안(IndexedDB)에만** 저장. 아이의 건강정보이므로 서버 DB 없이 시작
- **가족 공유**: MVP에서는 프로필을 QR코드나 JSON 파일로 내보내고 가져오기. 계정 기능은 나중에
- **배포**: Vercel

### 이미지 분석 API 응답 형식 (LLM에 이 JSON만 반환하도록 지시)
```json
{
  "product_name": "string | null",
  "ingredients": ["원재료명을 표기된 그대로, 하나씩"],
  "allergen_statement": ["'○○ 함유' 란에 적힌 항목"],
  "cross_contamination": ["'같은 제조시설' 문구의 항목"],
  "is_ingredient_label": true,
  "confidence": "high | medium | low",
  "unreadable_parts": "string | null"
}
```
- 성분표가 아닌 사진이면 `is_ingredient_label: false` → "성분표 부분을 찍어주세요" 안내
- 괄호 안 하위 원료도 펼쳐서 추출(예: "양념분말(대두, 밀, 새우)")

## 8. 안전 규칙 (반드시 지킬 것)

1. 앱은 진단하지 않음. 모든 결과 화면 하단에 "이 앱은 참고용이에요. 처음 먹는 음식은 부모님과 확인하세요" 표시
2. 인식이 불확실하면 **절대 초록을 띄우지 않음**(회색)
3. 위험 판단은 LLM이 아니라 **코드 규칙**으로
4. 첫 실행 때 부모가 프로필을 확인하기 전에는 홈에 "부모님 확인 필요" 배너 표시
5. 개인 건강정보를 외부로 보내지 않음. 이미지 분석 요청에도 **프로필은 보내지 않고 사진만** 보냄
6. 촬영 이미지는 분석 후 서버에 저장하지 않음

## 9. 개발 순서

1. **1단계:** 프로필 시드 데이터 + 동의어 사전 + 매칭 로직 + 단위 테스트
   - 테스트 예: "양념분말(대두, 밀, 새우)" → 새우=주의, 콩·밀=참고
   - "효모추출물" → 효모=위험
   - "본 제품은 땅콩을 사용한 제품과 같은 제조시설에서 제조" → 땅콩 한 단계 하향
2. **2단계:** 텍스트 직접 입력으로 결과 화면 완성(카메라 없이 먼저 검증)
3. **3단계:** 카메라 촬영 + 이미지 분석 API 연결
4. **4단계:** 프로필 관리 화면, 부모 PIN, 가족 상태 설정
5. **5단계:** 기록, PWA, 응급 버튼, 내보내기·가져오기
6. **6단계:** 실제 과자·라면·빵 성분표 20장 이상으로 인식률 점검

## 10. 나중에 (MVP 이후)

- 바코드 스캔 → 식품안전나라 공공 API로 원재료 자동 조회
- 가족 계정 동기화
- 외식 메뉴판 촬영
- 꽃가루 시즌 알림(참나무·자작나무 봄, 쑥 가을)
